## Core 5-minute loop: from CGM reading to dose

### Takeaway
A loop is triggered by `DeviceDataManager.recommendsLoop` after each pump/CGM refresh, rate-limited to one start per 3 minutes; `APSManager.determineBasal()` computes TDD, validates glucose, refreshes autosens (≤ every 30 min), rebuilds the profile, assembles ~13 JSON inputs, runs `meal` → `iob` → `determine-basal` JS in JavaScriptCore, stores a `Determination` in Core Data, and `enactDetermination()` sends the temp basal and then the SMB to the pump.

## determine-basal.js: deltas, BGI, deviation, eventualBG, prediction curves

### Takeaway
The algorithm is purely reactive: it computes 5-minute deltas from CGM history, subtracts the insulin-only expected change (BGI) to get a "deviation", projects that deviation forward in four 4-hour prediction curves (IOB, COB, UAM, ZT), and derives `eventualBG`, `minPredBG` and `minGuardBG` from those curves.

### Cited Findings
- Delta inputs (`glucose-get-last.js`): readings within 2.5 min of the newest are averaged into "now"; `delta` = mean of per-5-min deltas from points 2.5–7.5 min ago; `short_avgdelta` from 2.5–17.5 min; `long_avgdelta` from 17.5–42.5 min; processing stops at a `type:"cal"` record — [glucose-get-last.js](trio-oref/lib/glucose-get-last.js#L25-L88)
- `minDelta = min(delta, short_avgdelta)`, `minAvgDelta = min(short, long)`, `maxDelta = max(delta, short, long)` — [determine-basal.js](trio-oref/lib/determine-basal/determine-basal.js#L524-L526)
- `bgi = -activity * sens * 5` (mg/dL per 5 min); `deviation = 6 * (minDelta - bgi)`, and if negative it is recomputed with `minAvgDelta`, then `long_avgdelta` ("don't overreact to a big negative delta") — [L809-L819](trio-oref/lib/determine-basal/determine-basal.js#L809-L819)
- `naive_eventualBG = bg - iob*sens` (uses `min(sens, profile sens)` when IOB is negative); `eventualBG = naive_eventualBG + deviation` — [L822-L829](trio-oref/lib/determine-basal/determine-basal.js#L822-L829); `expectedDelta = bgi + (target - eventualBG)/24` i.e. the per-5-min rate needed to reach target in 2 h — [L28-L33](trio-oref/lib/determine-basal/determine-basal.js#L28-L33)
- Carb impact `ci = minDelta - bgi`, capped at `maxCarbAbsorptionRate = 30 g/h × CSF`, where `csf = sens / carbRatio` — [L928-L944](trio-oref/lib/determine-basal/determine-basal.js#L928-L944)
- `remainingCATimeMin = 3 h / sensitivityRatio`, raised to `mealCOB / 20 g/h`; `remainingCATime = remainingCATimeMin + 1.5 × hours since last carb entry` — [L945-L967](trio-oref/lib/determine-basal/determine-basal.js#L945-L967)
- `totalCI = ci/5*60*remainingCATime/2` (linear decay), `totalCA = totalCI/csf`; fork-custom: during an active meal window `totalCA *= mealWindowCOBDecayMultiplier` (default 1.0) — [L971-L983](trio-oref/lib/determine-basal/determine-basal.js#L971-L983); `remainingCarbs = min(90 cap, mealCOB - totalCA - carbs*(1-remainingCarbsFraction))`; `remainingCIpeak = remainingCarbs*csf*5/60/(remainingCATime/2)` (triangular "/\" absorption) — [L984-L995](trio-oref/lib/determine-basal/determine-basal.js#L984-L995)
- `slopeFromDeviations = min(slopeFromMaxDeviation, -slopeFromMinDeviation/3)` ("assume deviations will drop back down at least at 1/3 the rate they ramped up") — [L999-L1003](trio-oref/lib/determine-basal/determine-basal.js#L999-L1003); `cid = min(remainingCATime*6, mealCOB*csf/ci)` — [L1010-L1013](trio-oref/lib/determine-basal/determine-basal.js#L1010-L1013)
- Prediction loop over `iobArray` (48 × 5-min ticks = 4 h; truncated at 48 points): `predBGI = -tick.activity*sens*5`; `predZTBGI` uses `iobWithZeroTemp.activity`; `predDev = ci*(1 - n/12)` decays to zero over 60 min; `IOBpredBG += predBGI + predDev`; `ZTpredBG += predZTBGI` only; with logarithmic Dynamic ISF on (not sigmoid), each tick's ISF is recomputed from the predicted BG: `1800/(tdd*AF*ln(predBG/insulinFactor+1))` — [L1041-L1065](trio-oref/lib/determine-basal/determine-basal.js#L1041-L1065)
- `predCI = max(0, ci*(1 - n/max(cid*2,1)))`, `remainingCI` triangular ramp to `remainingCIpeak` at `remainingCATime/2`; `COBpredBG += predBGI + min(0,predDev) + predCI + remainingCI` — [L1069-L1079](trio-oref/lib/determine-basal/determine-basal.js#L1069-L1079)
- UAM: `predUCI = min(max(0, uci + n*slopeFromDeviations), max(0, uci*(1 - n/36)))` (3 h linear fallback); `UAMpredBG += predBGI + min(0,predDev) + predUCI` — [L1082-L1103](trio-oref/lib/determine-basal/determine-basal.js#L1082-L1103)
- Min-guard values are taken from the first tick onward; `minIOBPredBG` and `minCOBPredBG` only after `insulinPeakTime = 90` minutes (hard-coded "60m regardless of insulin type" + 30 min delivery allowance); `minUAMPredBG` after 60 min (`length > 12`) — [L1111-L1131](trio-oref/lib/determine-basal/determine-basal.js#L1111-L1131)
- Post-processing: IOB/UAM/ZT curves clamped to 39–401, COB to 39–1500; trailing identical values trimmed; `eventualBG = max(eventualBG, last COBpredBG)` when COB>0 and `ci>0 || remainingCIpeak>0`; then `max(eventualBG, last UAMpredBG)` when UAM enabled — [L1143-L1194](trio-oref/lib/determine-basal/determine-basal.js#L1143-L1194)
- `avgPredBG` = COB/UAM blend by `fractionCarbsLeft = mealCOB/carbs`, else average with IOB; floored at `minZTGuardBG` — [L1203-L1220](trio-oref/lib/determine-basal/determine-basal.js#L1203-L1220); `minGuardBG` = blend of `minCOBGuardBG`/`minUAMGuardBG` by fractionCarbsLeft, else UAM guard, else IOB guard — [L1223-L1234](trio-oref/lib/determine-basal/determine-basal.js#L1223-L1234)
- `minZTUAMPredBG`: averages `minUAMPredBG` with `minZTGuardBG` when ZT guard is below threshold, blends between threshold and target, averages if ZT guard > UAM — [L1237-L1255](trio-oref/lib/determine-basal/determine-basal.js#L1237-L1255); `minPredBG` selection: with carbs → `max(minIOBPredBG, minCOBPredBG, blendedMinPredBG)` (or `minZTUAMPredBG` if COB expired); pure UAM → `max(minIOBPredBG, minZTUAMPredBG)`; then `min(minPredBG, avgPredBG)` and capped at `maxCOBPredBG` "if the COB line falls off a cliff" — [L1257-L1296](trio-oref/lib/determine-basal/determine-basal.js#L1257-L1296)
- Upstream documentation confirms the same structure: "eventualBG = naive_eventualBG + deviation"; BGI is "the degree to which BG 'should' be rising or falling based on insulin activity alone"; UAM "assumes they'll peak immediately and start decreasing at ⅓ of the rate they increased"; ZT is the "worst likely case" — [OpenAPS docs: Understand determine-basal](https://openaps.readthedocs.io/en/latest/docs/While%20You%20Wait%20For%20Gear/Understand-determine-basal.html)

### Inferences
- Rising glucose is only "detected" indirectly: a positive deviation (observed delta exceeding insulin-expected delta) raises `ci`, `eventualBG`, and the UAM curve; there is no explicit meal-onset detector, acceleration or jerk term in the upstream JS (the fork's Kalman/acceleration detector exists only in Swift shadow code — see custom-modules section).
- Falling glucose is handled by multiple layers: negative deviation is damped (uses longer averages), `minDelta < expectedDelta` reverts to neutral temp, and `minGuardBG`/ZT curves drive zero temps and SMB disablement.
- The 90-minute wait before `minIOBPredBG`/`minCOBPredBG` can be set means SMB sizing ignores predicted lows inside the first 1.5 h; `minGuardBG` (no wait) is the only guard for that window.

### Gaps
- None material; the prediction code was read in full.

## Decision tree: temp basal vs SMB vs zero temp, low-glucose safety, SMB sizing, magic constants

### Takeaway
After CGM/data-sanity checks, the code returns on the first matching branch: predictive low-glucose suspend (zero temp 30–120 min) → eventualBG below target (low temp, 2× faster than a naive controller) → falling faster than expected (neutral) → in range (neutral) → IOB over max (neutral) → otherwise compute `insulinReq`, deliver at most `smb_delivery_ratio × insulinReq` capped by `maxSMBBasalMinutes`/`maxUAMSMBBasalMinutes` of basal, and set a 30-min high temp for the remainder.

### Cited Findings
- CGM sanity: if `bg <= 10 || bg === 38 || noise >= 3 || minAgo > 12 || minAgo < -5`: replace any high temp with a 30-min neutral temp, shorten zero temps longer than 30 min, else do nothing, and return — [L534-L579](trio-oref/lib/determine-basal/determine-basal.js#L534-L579)
- Targets: `min_bg = max_bg = target_bg = profileTarget` (Trio uses a single target; `profile.max_bg` is set to `profileTarget`) — [L593-L608](trio-oref/lib/determine-basal/determine-basal.js#L593-L608); profile generation bounds targets to 80–200 — [profile/targets.js](trio-oref/lib/profile/targets.js#L67-L78)
- `threshold = min_bg - 0.5*(min_bg-40)` (80→60, 100→70, 120→80), then `min(max(threshold_setting, threshold, 60), 120)` — [L733-L737](trio-oref/lib/determine-basal/determine-basal.js#L733-L737); `threshold_setting` default 60 — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L54)
- Temp mismatch safety: if the running temp rate ≠ pumphistory `lastTemp.rate` and the last temp is >10 min old, or if the last temp ended >5 min ago, cancel the temp — [L780-L803](trio-oref/lib/determine-basal/determine-basal.js#L780-L803)
- SMB enablement (`enable_smb`): scheduled-off window from overrides (uses `new Date(time.getHours())`, i.e. a Date whose ms value equals the hour) — [L47-L70](trio-oref/lib/determine-basal/determine-basal.js#L47-L70); disabled if `!microBolusAllowed`, if a temp target >100 is set without `allowSMB_with_high_temptarget`, or Bolus-Wizard activity without `A52_risk_enable` — [L72-L81](trio-oref/lib/determine-basal/determine-basal.js#L72-L81); enabled by `enableSMB_always`, `enableSMB_with_COB` (mealCOB>0), `enableSMB_after_carbs` (carbs in 6 h), `enableSMB_with_temptarget` (TT<100), `enableSMB_high_bg` (bg ≥ `enableSMB_high_bg_target`, default 110), and fork-custom: an active meal window — [L84-L146](trio-oref/lib/determine-basal/determine-basal.js#L84-L146). All `enableSMB_*` and `enableUAM` default `false`; `maxSMBBasalMinutes = maxUAMSMBBasalMinutes = 30`, `smbInterval = 3`, `bolusIncrement = 0.1`, `smbDeliveryRatio = 0.5`, `maxDeltaBGthreshold = 0.2`, `maxIOB = 0` — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L4-L54)
- SMB disabled if `minGuardBG < threshold` — [L1358-L1366](trio-oref/lib/determine-basal/determine-basal.js#L1358-L1366); or if `maxDelta > maxDelta_bg_threshold(0.2, capped 0.4) × bg` ("sudden rises (often caused by calibrations…)") — [L1369-L1380](trio-oref/lib/determine-basal/determine-basal.js#L1369-L1380)
- carbsReq: `carbsReqBG = naive_eventualBG` (or `minGuardBG` if <40); `bgUndershoot = threshold - carbsReqBG`; `zeroTempEffect = basal*sens*minutesAboveThreshold/60`; `COBforCarbsReq = max(0, mealCOB - 0.25*carbs)`; `carbsReq = (bgUndershoot - zeroTempEffect)/csf - COBforCarbsReq`; reported if `≥ carbsReqThreshold` (1 g) and `minutesAboveThreshold ≤ 45` — [L1318-L1403](trio-oref/lib/determine-basal/determine-basal.js#L1318-L1403)
- Predictive LGS: skipped if `bg < threshold` but IOB < `-basal*20/60` and rising faster than expected; otherwise if `bg < threshold || minGuardBG < threshold` → zero temp for `round((target - minGuardBG)/sens*60/basal / 30)*30`, clamped 30–120 min — [L1407-L1430](trio-oref/lib/determine-basal/determine-basal.js#L1407-L1430)
- `skip_neutral_temps` cancels temps after :55 when SMBs are off — [L1434-L1441](trio-oref/lib/determine-basal/determine-basal.js#L1434-L1441)
- `eventualBG < min_bg` branch: if rising faster than expected and no carbsReq → neutral 30-min temp (or 30-min zero temp if `naive_eventualBG < 40`); else `insulinReq = 2*min(0,(eventualBG-target)/sens)` ("multiply by 2 to low-temp faster"), scaled by `minDelta/expectedDelta` when barely falling, `rate = basal + 2*insulinReq`; raise rate if current temp delivers ≥30% basal less than needed; keep temp if `rate ≥ 0.8×current`; else zero temp up to 120 min sized by `(target - naive_eventualBG)/sens` — [L1446-L1528](trio-oref/lib/determine-basal/determine-basal.js#L1446-L1528)

- The `enable_smb` scheduled-off logic works only by coincidence of `Date.valueOf()` equalling the hour in milliseconds (line 53); it is brittle.

## Dynamic ISF, TDD adjustment, temp targets / exercise, autosens, autotune

### Takeaway
Sensitivity is set by exactly one of: temp-target-derived ratio (half-basal-target formula), autosens ratio (median of non-meal deviations over 8 h/24 h, clamped 0.7–1.2), or Dynamic ISF (logarithmic or sigmoid function of BG and TDD, also clamped by autosens min/max). CR is never adapted; autotune is present in the JS bundle and a UI module but is not wired into the build or the profile.

### Cited Findings
- Dynamic ISF is enabled by `preferences.useNewFormula` and disabled when `autosens_min == autosens_max`, max < 1, min > 1, when an exercise setting is on and target ≥ 118, or (Swift) when TDD data is insufficient — [L241-L311](trio-oref/lib/determine-basal/determine-basal.js#L241-L311), [L346-L356](trio-oref/lib/determine-basal/determine-basal.js#L346-L356), [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L484-L488); sufficiency = ≥ 75% of 7×288 `TDDStored` rows in last 7 days — [TDDStorage.swift](Trio/Sources/APS/Storage/TDDStorage.swift#L607-L636)
- `insulinFactor = 120 - peak` with peak 65 (rapid-acting) / 50 (ultra-rapid) or custom `insulinPeakTime` — [L364-L386](trio-oref/lib/determine-basal/determine-basal.js#L364-L386)
- TDD input: `tdd = currentTDD` (last 24 h) unless `weightPercentage < 1 && weightedAverage > 1`, then `tdd = weightedAverage` — [L388-L394](trio-oref/lib/determine-basal/determine-basal.js#L388-L394); Swift computes `weightedTDD = wp × avg(last 2 h TDD rows) + (1-wp) × avg(10 days)` and `average_total_data` = 10-day average — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L574-L587); `weightPercentage` default 0.35 in Swift vs 0.65 in JS profile defaults — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L50), [profile/index.js](trio-oref/lib/profile/index.js#L77)

- Temp target sensitivity: if (`high_temptarget_raises_sensitivity`/`exercise_mode` and TT > 100) or (`low_temptarget_lowers_sensitivity` and TT < 100): `c = halfBasalTarget - 100; sensitivityRatio = min(c/(c + target - 100), autosens_max)`; `half_basal_exercise_target` default 160 — [L613-L640](trio-oref/lib/determine-basal/determine-basal.js#L613-L640), [Preferences.swift](Trio/Sources/Models/Preferences.swift#L17); otherwise `sensitivityRatio = autosens_data.ratio` — [L641-L650](trio-oref/lib/determine-basal/determine-basal.js#L641-L650); with Dynamic ISF a low TT raises the ratio by `100/target` — [L653-L661](trio-oref/lib/determine-basal/determine-basal.js#L653-L661)
- Basal scaling: `basal = current_basal × overrideFactor × sensitivityRatio` only when Dynamic ISF is off — [L663-L671](trio-oref/lib/determine-basal/determine-basal.js#L663-L671); ISF: `sens = profile.sens / sensitivityRatio` — [L745-L758](trio-oref/lib/determine-basal/determine-basal.js#L745-L758); autosens may also move the target: `new_target = (target-60)/ratio + 60`, floor 80, when `sensitivity_raises_target`/`resistance_lowers_target` — [L686-L703](trio-oref/lib/determine-basal/determine-basal.js#L686-L703)

## Meal handling: COB model, carb absorption assumptions, UAM, and the fork's meal-window machinery

### Takeaway
Upstream COB is "carbs entered minus carbs absorbed", where absorption per 5-min bucket is `max(deviation, currentDeviation/2, min_5m_carbimpact) × CR / ISF`, so COB decays at a minimum of 8 mg/dL-equivalent per 5 min whether or not BG is rising; the fork layers an "I'm eating" meal window (Action Button shortcut) that forces UAM, boosts SMB ratio to 0.8, doubles SMB minute caps, floors `insulinReq`, optionally slows COB decay, and can inject phantom COB (manual 20 g on classifier upgrade; automatic residual-based injector default OFF).

### Cited Findings
- `meal/total.js`: carbs within `maxMealAbsorptionTime` (default 6 h) are summed; for each entry, `calcMealCOB` returns carbs absorbed since that entry, `mealCOB = max(mealCOB, carbs - absorbed)`; COB capped at `maxCOB` (120 g); COB forced to 0 if `currentDeviation`/`maxDeviation` undefined ("zombie-carb safety") — [meal/total.js](trio-oref/lib/meal/total.js#L50-L137)
- `cob.js`: considers BG only within `maxMealAbsorptionTime` h after the meal; interpolates gaps > 8 min (max 4 h); `deviation = delta - bgi` with `sens` from the ISF schedule; `ci = max(deviation, currentDeviation/2, min_5m_carbimpact)`; `absorbed = ci × carb_ratio / sens`; also computes `slopeFromMaxDeviation`/`slopeFromMinDeviation` over the last 45 min for UAM — [cob.js](trio-oref/lib/determine-basal/cob.js#L52-L59), [L76-L106](trio-oref/lib/determine-basal/cob.js#L76-L106), [L146-L190](trio-oref/lib/determine-basal/cob.js#L146-L190); defaults `min_5m_carbimpact 8` ("24 g/hr at a CSF of 4"), `maxCOB 120`, `maxMealAbsorptionTime 6`, `remainingCarbsCap 90`, `remainingCarbsFraction 1` — [profile/index.js](trio-oref/lib/profile/index.js#L27-L34), [Preferences.swift](Trio/Sources/Models/Preferences.swift#L18-L25)
- In determine-basal, un-absorbed carbs are assumed to absorb at 20 g/h minimum (`assumedCarbAbsorptionRate`) within `remainingCATime` with a triangular profile; observed CI is capped at 30 g/h — [L938-L995](trio-oref/lib/determine-basal/determine-basal.js#L938-L995); upstream doc: "Meals of 60g or less are assumed to absorb over about 3 hours… Carbs are capped at 90g" — [OpenAPS docs](https://openaps.readthedocs.io/en/latest/docs/While%20You%20Wait%20For%20Gear/Understand-determine-basal.html)
- UAM is only a prediction curve (`UAMpredBGs`) driven by current deviation and deviation slope; it raises `eventualBG` and participates in `minPredBG`; it requires `enableUAM` — [L916-L920](trio-oref/lib/determine-basal/determine-basal.js#L916-L920), [L1082-L1103](trio-oref/lib/determine-basal/determine-basal.js#L1082-L1103), [L1177-L1190](trio-oref/lib/determine-basal/determine-basal.js#L1177-L1190)
- Rescue carbs (`isRescueCarbs == YES`) are hidden from oref's `meal.json` by predicate; FPU-derived chunks (`isFPU`) are counted as ordinary carbs by oref but excluded from the fork's estimator sums — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L186-L196), [APSManager.swift](Trio/Sources/APS/APSManager.swift#L1436-L1452)
- Fork-custom "Tough Meal" (predates meal window): when active (`toughMealActivationDate`, duration default 7 h, hard cap 6 h) and BG ≥ 120, delta ≥ −1, IOB < 75% maxIOB, and (COB > 0 or bolus < 4 h ago): `effective_autosens_max = max(autosens_max, 1.4)` and `toughMealSMBActive` — [L268-L298](trio-oref/lib/determine-basal/determine-basal.js#L268-L298), [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L591-L606), [TrioSettings.swift](Trio/Sources/Models/TrioSettings.swift#L73-L79); SMB cap multiplier 1.5×/2.0×/2.5× when BG > 150/200/250, then microBolus capped at 75% (configurable) of insulinReq — [L1774-L1786](trio-oref/lib/determine-basal/determine-basal.js#L1774-L1786), [L1815-L1820](trio-oref/lib/determine-basal/determine-basal.js#L1815-L1820)
- Fork-custom meal window: activated by `AnnounceMealIntentRequest` (`s.mealWindowActivationDate = now`), default 90 min, extended to 240 min once carbs are confirmed, hard cap 360 min, auto-enables tough-meal state — [AnnounceMealIntentRequest.swift](Trio/Sources/Shortcuts/Meal/AnnounceMealIntentRequest.swift#L108), [TrioSettings.swift](Trio/Sources/Models/TrioSettings.swift#L83-L102), [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L611-L633). - Auto phantom COB injector (fork, default OFF, "ENABLE" typed confirmation): `impliedSoFar = max(0, bg - bgAtActivation)×CR/ISF + max(0, iob)×CR`; `unmodeled = impliedSoFar − (loggedCarbs + priorInjected)`; inject `min(unmodeled×(1−damping 0.5), perLoopCap 8 g)` subject to classifier ≥ Medium, `shortAvgDelta > 0`, per-window cap 200 g; never withdrawn — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L1276-L1344), [L1346-L1430](Trio/Sources/APS/APSManager.swift#L1346-L1430), [TrioSettings.swift](Trio/Sources/Models/TrioSettings.swift#L205-L222); commit message gives the motivating case "un-logged lunch climbed 120→174 over 80 min with only 4.15U of SMBs fired" (git show 3fc578a)

### Inferences
- The meal-window stack is a set of multiplicative overrides on top of oref's unchanged model rather than a different model; because each knob (SMB ratio 0.8, 2× minute cap, insulinReq floor, phantom COB floor, 1.4 autosens max, 2.5× tough-meal cap) composes multiplicatively, worst-case aggression inside a window is hard to reason about (e.g., basal 1 U/h → upstream max SMB 0.5 U; in-window with BG > 250: 0.5 × 2 × 2.5 = 2.5 U per 3 min, limited by 75% of insulinReq and `max_iob`).
- Phantom COB "lies" to the COB model (acknowledged in comments at L194 "Lying to oref is high-risk"); because `enableSMB_with_COB` and `eventualBG` both key off `mealCOB`, injected grams simultaneously enable SMBs and raise predictions.
- The classifier is a hand-tuned threshold state machine on raw 5-min BG; there is no probabilistic meal detection in the dosing path.

## IOB model: insulin activity curves and bolus vs temp basal accounting

### Takeaway
IOB is computed every 5 min for 4 h from a treatment list in which temp basals are converted into ±0.05 U micro-events relative to the scheduled (autosens-scaled) basal; the activity curve is the Loop-style exponential with peak 75 min (rapid-acting) or 55 min (ultra-rapid) and a DIA forced to ≥ 5 h; there is no distinct Lyumjev curve.

### Cited Findings
- `iob/index.js`: `find_insulin(inputs)` and a second list with a 240-min future zero temp (`iobWithZeroTemp`); `iobArray` computed at 5-min steps to 4 h "regardless of DIA"; `lastBolusTime` and `lastTemp` attached to element 0 — [iob/index.js](trio-oref/lib/iob/index.js#L7-L82)
- `iob/total.js`: DIA forced ≥ 3 h, and ≥ 5 h for `rapid-acting`/`ultra-rapid`; peak 75 / 55; only treatments within DIA count; treatments with `insulin < 0.1` are accounted as basal IOB, others as bolus IOB — [iob/total.js](trio-oref/lib/iob/total.js#L21-L90)
- `iob/calculate.js`: exponential curve from LoopKit issue #388: `tau = peak×(1−peak/end)/(1−2peak/end)`, `a = 2tau/end`, `S = 1/(1−a+(1+a)e^(−end/tau))`, activity and IOB formulas; custom peak clamped 50–120 (rapid) or 35–100 (ultra-rapid); unsupported curve logs an error — [iob/calculate.js](trio-oref/lib/iob/calculate.js#L81-L141); bilinear legacy curve peak 75 / end 180 scaled by DIA — [L34-L78](trio-oref/lib/iob/calculate.js#L34-L78)
- `iob/history.js`: temp basals (after splitting at basal-schedule boundaries and around suspends, with `suspend_zeros_iob`) are turned into `tempBolus` events of ±0.05 U spaced evenly over the temp's duration, where `netBasalRate = temp.rate − scheduledRate × sensitivityRatio` (autosens or exercise TT ratio) — [iob/history.js](trio-oref/lib/iob/history.js#L508-L568); a zero temp starting 1 min in the future is appended to "ignore future temps and reduce predBG oscillation" — [L366-L377](trio-oref/lib/iob/history.js#L366-L377)
- Swift supplies pump history as bolus, temp basal duration/rate, suspend/resume, rewind, prime DTOs; a simulated bolus can be injected for the bolus calculator — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L299-L358)
- Preferences: `curve` default `.rapidActing`, `insulinPeakTime 75`, `useCustomPeakTime` — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L37-L39); DIA comes from pump settings `insulin_action_curve` and must be > 1 — [profile/index.js](trio-oref/lib/profile/index.js#L131-L137)

### Inferences
- Because net-basal insulin is quantised into 0.05 U events and scheduled basal is assumed "zero IOB", IOB represents deviation from the user's basal schedule, so basal-schedule errors directly bias IOB, BGI, deviation, COB absorption and autosens simultaneously.
- The exponential curve's single `(peak, DIA)` pair is static: no absorption-site, temperature, exercise or dose-size dependence.

### Gaps
- None.

## Safety limits, suspend behaviour, stale/noisy CGM handling

### Takeaway
Hard limits are `max_iob` (SMB and insulinReq), `maxSafeBasal = min(max_basal, 3×max_daily_basal, 4×current_basal)`, `maxCOB`, `maxBolus` from SMB minutes, `smb_delivery_ratio ≤ 1`, `SMBInterval`, and 12-minute CGM staleness enforced in both Swift and JS; pump suspend skips enactment; the noise-based guards are inert because Trio does not send a noise value.

### Cited Findings
- `max_iob` caps both SMB and high-temp insulinReq and triggers neutral temp when exceeded — [L1598-L1607](trio-oref/lib/determine-basal/determine-basal.js#L1598-L1607), [L1687-L1691](trio-oref/lib/determine-basal/determine-basal.js#L1687-L1691); default 0 — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L4)
- Max basal: `getMaxSafeBasal` and clamp in `setTempBasal` — [basal-set-temp.js](trio-oref/lib/basal-set-temp.js#L10-L28); `max_daily_safety_multiplier 3`, `current_basal_safety_multiplier 4` — [profile/index.js](trio-oref/lib/profile/index.js#L12-L13)
- Stale glucose: Swift refuses to loop if newest reading > 12 min old or < 3 readings in the last hour — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L463-L486); JS replaces high temps/shortens zero temps when `minAgo > 12 || minAgo < -5` — [L544-L579](trio-oref/lib/determine-basal/determine-basal.js#L544-L579)
- Pump suspended → `enactDetermination` returns without enacting; manual temp basal → error — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L1694-L1702); `suspend_zeros_iob` default true treats suspends as zero delivery — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L42), [iob/history.js](trio-oref/lib/iob/history.js#L420-L424)
- Orphaned resumes on cold start are filtered to avoid negative IOB "which drives negative IOB and can cause excessive insulin delivery" (issue #898) — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L267-L274)
- Determination must be < 30 min old to enact — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L1683-L1686)
- Upstream 400 mg/dL guard was removed from this oref version ("Remove 400 / shouldProtectDueToHIGH guard") — [oref0_source_version.txt](oref0_source_version.txt#L5-L6); predictions are clamped at 401 (IOB/UAM/ZT) and 1500 (COB) — [L1144](trio-oref/lib/determine-basal/determine-basal.js#L1144), [L1166](trio-oref/lib/determine-basal/determine-basal.js#L1166)
- Manual bolus safety validator (max bolus, max IOB, recent-bolus 20% rule) is Swift-side and tested — [TrioTests/BolusSafetyTests/BolusSafetyValidatorTests.swift](TrioTests/BolusSafetyTests/BolusSafetyValidatorTests.swift#L19-L104)

### Inferences
- There is no insulin-delivery rate limiter outside the per-SMB cap and `max_iob`; a sequence of maximal SMBs every 3 minutes is permitted as long as `max_iob` headroom exists.

### Gaps
- Pump-side bolus/temp limits (LoopKit `PumpManager` max bolus) were not examined.

## User-maintained settings vs automatically adapted parameters

### Takeaway
Users must enter and maintain basal schedule, ISF schedule, CR schedule, target(s), DIA, insulin curve/peak, max IOB, max basal, and the SMB/UAM/Dynamic-ISF preference flags; the only parameters the loop adapts are a single sensitivity ratio (autosens or Dynamic ISF, 0.7–1.2) applied to ISF (and basal/target in some modes). CR, DIA, peak, carb-absorption constants and basal shape are never learned in this build.

### Cited Findings
- Profile inputs required: pump settings (DIA), bg targets, basal profile (`current_basal` must be > 0, `max_daily_basal` > 0, `max_basal` ≥ 0.1), ISF (`sens ≥ 5`), carb ratios (1–150) — [profile/index.js](trio-oref/lib/profile/index.js#L131-L194), [profile/carbs.js](trio-oref/lib/profile/carbs.js#L22-L25); file names in [Constants.swift](Trio/Sources/APS/OpenAPS/Constants.swift#L29-L42)
- Preference list with defaults — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L4-L54)
- Adapted automatically: autosens ratio (ISF; basal when Dynamic ISF off; target when `sensitivity_raises_target`/`resistance_lowers_target`) — [L641-L703](trio-oref/lib/determine-basal/determine-basal.js#L641-L703); Dynamic ISF ratio — [L404-L455](trio-oref/lib/determine-basal/determine-basal.js#L404-L455); TDD-ratio basal when `tddAdjBasal` — [L673-L682](trio-oref/lib/determine-basal/determine-basal.js#L673-L682)
- Not adapted: autotune disabled (see above); dynamic CR removed upstream — [oref0_source_version.txt](oref0_source_version.txt#L18)
- Fork: therapy profiles can switch whole ISF/CR/basal sets on a schedule (`profileManager.checkForScheduledSwitch()` on every heartbeat) — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L238-L242); inverse calibration suggests CR/ISF from verified meals but is user-applied — [docs/MEAL_INTELLIGENCE_v3_SPEC.md](docs/MEAL_INTELLIGENCE_v3_SPEC.md#L12-L30)

### Inferences
- The algorithm's correctness depends on three user-entered ratios (basal, ISF, CR) being right simultaneously; errors in one are partially absorbed by autosens but attributed to "sensitivity", not to the wrong parameter.

### Gaps
- None.

## Fork-custom modules: SignalProcessing (Kalman), SmartSense, PhysioTesting, AIInsights — do they feed dosing?

### Takeaway
The 10-file `APS/SignalProcessing` pipeline (adaptive Kalman filter, residual-based carb-absorption estimator, macro meal model, daily state vector from Garmin, exercise sensitivity model, adaptive learning) runs every loop in shadow mode and only logs; SmartSense blends Garmin signals with autosens into a ratio shown in the bolus calculator and logged, but nothing from these modules is written into oref inputs. Only the meal-window/classifier/phantom-COB path changes dosing.

### Cited Findings
- Pipeline protocol: "Each phase runs in shadow mode (compute + log) by default. Phase toggles gate whether computed values feed into oref decisions." — [OrefSignalPipeline.swift](Trio/Sources/APS/SignalProcessing/OrefSignalPipeline.swift#L5-L13); `processGlucose` runs Kalman + meal detection, residual (`residualCalculator.update`), macro model with `orefCOB: nil`, learning snapshot, then logs to `SignalStore` and publishes — [L150-L245](Trio/Sources/APS/SignalProcessing/OrefSignalPipeline.swift#L150-L245)
- Call site in APSManager is explicitly "(Phase 1: compute and log, no dosing changes)" — [APSManager.swift](Trio/Sources/APS/APSManager.swift#L509-L522); consumers of pipeline output are telemetry (`sig = signalPipeline.latestOutput`), `TreatmentsStateModel` snapshot fields, `MealDecisionExporter`, `PhysioTestingStateModel` (adaptive learning UI) — grep results: [APSManager.swift:632](Trio/Sources/APS/APSManager.swift#L632), [TreatmentsStateModel.swift:962-967](Trio/Sources/Modules/Treatments/TreatmentsStateModel.swift#L962-L967), [PhysioTestingStateModel.swift:491-535](Trio/Sources/Modules/PhysioTesting/PhysioTestingStateModel.swift#L491-L535)
- Kalman filter: state [BG, velocity, acceleration]; `qBaseBG 0.5`, `measurementNoise 36 (≈6 mg/dL SD)`, volatility-adaptive Q — [AdaptiveKalmanFilter.swift](Trio/Sources/APS/SignalProcessing/AdaptiveKalmanFilter.swift#L1-L38)
- Residual: `Residual = BG_actual − BG_expected(activity)`; carb rate = `(dResidual/dt)/ISF × CR`; EMA 0.3 — [BGResidualCalculator.swift](Trio/Sources/APS/SignalProcessing/BGResidualCalculator.swift#L1-L33)
- Macro meal model: fiber discount 0.5, carb 0.5 g/min, protein onset/peak/duration 120/210/360 min, fat 180/300/480 min, fat delay 3 min/g; "When the toggle is OFF, this runs in shadow mode" — [MacroMealModel.swift](Trio/Sources/APS/SignalProcessing/MacroMealModel.swift#L1-L40)

## Concrete weaknesses and brittle points observed in the code

### Takeaway
The dosing core is a deterministic, reactive, single-scalar-adaptive controller with hard-coded physiology constants, multiplicative safety caps, and several Trio-specific dead or inert paths; the fork's additions address symptoms (SMB size, COB decay) via multiplicative overrides and COB fabrication rather than by changing the model.

### Cited Findings
- Reactive-only: dosing starts only after `minDelta − bgi > 0` produces positive deviation/CI; no explicit meal-onset detection in JS — [L811-L829](trio-oref/lib/determine-basal/determine-basal.js#L811-L829), [L928-L929](trio-oref/lib/determine-basal/determine-basal.js#L928-L929); deviation uses the minimum of 5-min and 15-min deltas and 45-min data for slopes, adding 10–45 min of lag — [glucose-get-last.js](trio-oref/lib/glucose-get-last.js#L52-L63), [cob.js](trio-oref/lib/determine-basal/cob.js#L61-L68)
- Linear/triangular COB decay with fixed constants: `min_5m_carbimpact 8`, 20 g/h assumed, 30 g/h max, 3 h min, 90 g cap, 60-min deviation decay, 3 h UAM decay, 4 h prediction horizon — [L938-L995](trio-oref/lib/determine-basal/determine-basal.js#L938-L995), [L1050](trio-oref/lib/determine-basal/determine-basal.js#L1050), [L1085](trio-oref/lib/determine-basal/determine-basal.js#L1085), [L1106-L1109](trio-oref/lib/determine-basal/determine-basal.js#L1106-L1109); COB decays at ≥ `min_5m_carbimpact` even when BG is flat — [cob.js](trio-oref/lib/determine-basal/cob.js#L185-L189); no fat/protein model in the dosing path (FPU entries are just carbs)
- Dependence on user ratios: `csf = sens/carbRatio` drives both absorption accounting and predictions; `sens` is the only adapted quantity — [L935](trio-oref/lib/determine-basal/determine-basal.js#L935)
- Per-cycle SMB ceiling: `maxBolus = basal × 30 min/60` and `smb_ratio 0.5` → half of insulinReq, every ≥ 3 min — [L1744-L1822](trio-oref/lib/determine-basal/determine-basal.js#L1744-L1822); documented real-world failure (insulinReq 1.0–3.2 U, delivered 0.5–0.6 U) — [docs/TOUGH_MEAL_HANDLING.md](docs/TOUGH_MEAL_HANDLING.md#L47-L58)
- Hard-coded 90-min wait before `minIOBPredBG`/`minCOBPredBG` "regardless of insulin type" — [L1116-L1128](trio-oref/lib/determine-basal/determine-basal.js#L1116-L1128)
- No exercise input except temp targets / `exercise_mode` scalar; Garmin/HealthKit data never reaches oref — [L613-L640](trio-oref/lib/determine-basal/determine-basal.js#L613-L640), [ExerciseSensitivityModel.swift](Trio/Sources/APS/SignalProcessing/ExerciseSensitivityModel.swift#L9-L10)
- Inert noise handling: `noise`, `device`, `last_cal` never supplied by Swift — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L172-L178) vs [glucose-get-last.js](trio-oref/lib/glucose-get-last.js#L27-L32), [determine-basal.js](trio-oref/lib/determine-basal/determine-basal.js#L719-L731)
- Dynamic ISF overwrites `autosens_data.ratio` and basal is not ratio-scaled when Dynamic ISF is on (unless `tddAdjBasal`) — [L455](trio-oref/lib/determine-basal/determine-basal.js#L455), [L663-L682](trio-oref/lib/determine-basal/determine-basal.js#L663-L682); `weightPercentage` default differs between Swift (0.35) and JS (0.65) — [Preferences.swift](Trio/Sources/Models/Preferences.swift#L50), [profile/index.js](trio-oref/lib/profile/index.js#L77)
- Fork brittleness: nested JSON fields must be re-parsed by substring scanning because Codable "silently drops" them — [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L35-L52), [L519-L536](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L519-L536); classifier upgrade permanently flips the user setting `mealWindowPhantomCOB = true` ("stays on for any future window until the user turns it off manually") — [MealClassifier.swift](Trio/Sources/APS/MealClassifier.swift#L262-L271); loop state (window, classifier phases, injected grams) lives in `TrioSettings` JSON rather than a dedicated store — [TrioSettings.swift](Trio/Sources/Models/TrioSettings.swift#L83-L129)
- Multiplicative stacking of custom caps (1.4 autosens max, 2× SMB minutes, 1.5–2.5× tough-meal cap, 0.8 ratio, insulinReq floor, phantom COB) all gated by the same rising/IOB-headroom heuristics — [L272-L298](trio-oref/lib/determine-basal/determine-basal.js#L272-L298), [L1626-L1684](trio-oref/lib/determine-basal/determine-basal.js#L1626-L1684), [L1736-L1742](trio-oref/lib/determine-basal/determine-basal.js#L1736-L1742), [L1774-L1820](trio-oref/lib/determine-basal/determine-basal.js#L1774-L1820)
- Autotune UI module present but unbuildable/unreachable; autosens/dynamic ISF are the only live learners — [AutotuneConfigStateModel.swift](Trio/Sources/Modules/AutotuneConfig/AutotuneConfigStateModel.swift#L56), [OpenAPS.swift](Trio/Sources/APS/OpenAPS/OpenAPS.swift#L804)
- Prediction uses one ISF for all 4 h (except log-dynISF per-tick) and ignores time-of-day ISF/CR schedule changes within the horizon — [L1044-L1045](trio-oref/lib/determine-basal/determine-basal.js#L1044-L1045), [cob.js](trio-oref/lib/determine-basal/cob.js#L121)
- Upstream-removed 400 mg/dL guard means no high-glucose special handling beyond prediction clamps — [oref0_source_version.txt](oref0_source_version.txt#L5-L6)

### Inferences
- A redesign could keep the Swift input assembly (`OpenAPS.determineBasal`, `TrioCustomOrefVariables`) and pump enactment (`enactDetermination`) as stable interfaces, replacing only the JS `determine-basal`/`meal`/`autosens` stage; the existing shadow pipeline already consumes the same inputs, which makes an A/B "shadow vs live" comparison feasible with existing telemetry.
- The highest-leverage structural changes implied by the code are: an explicit meal-onset/absorption estimator feeding COB (replacing phantom COB), a non-linear/macro-aware absorption model, per-parameter (ISF/CR/basal) rather than single-scalar adaptation, and replacing the fixed 30-min-of-basal SMB cap with a model-based delivery limit.

### Gaps
- No runtime data was analysed here; weaknesses are stated from code structure and the fork's own documented case studies.
