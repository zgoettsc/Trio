# Trio Telemetry

Auto-generated by the Trio iOS app. Contains meal-window events, loop decisions,
per-meal outcome summaries, and daily settings snapshots used to tune the
algorithm.

## Layout

```
telemetry/
  YYYY-MM/
    DD/
      events.jsonl    one-line-JSON events (meal-window lifecycle, floor activations,
                      carb entries, bolus events). Append-only.
      loop.jsonl      one row per loop pass (~5 min cadence). BG signal, IOB, COB,
                      insulinReq, smbDelivered, oref reason, meal-window flags.
      summary.jsonl   per-meal-window rollups. Each window yields TWO rows: one at
                      close (metadata) and one at close+6h (outcomes filled in).
      settings.json   daily snapshot of profile schedule (basal/ISF/CR by hour),
                      algorithm preferences, active overrides.
```

Branch is intentionally an orphan (no shared history with `main`) so source diffs
aren't polluted with telemetry commits.

## Privacy

This branch is private. Files contain timestamps, BG readings, insulin doses, and
settings — enough to reconstruct your day-to-day glucose management but no PII
beyond what's already in the parent repo's commit history.

Retention: directories older than 30 days are auto-deleted by the app once daily
after a successful push. `summary.jsonl` files are preserved indefinitely.

## What to do with the data

See **ANALYSIS_METHODS.md** for the full runbook. Short version:

- Clone the branch: `git clone --branch telemetry --single-branch <repo>`
- `cat telemetry/*/*/loop.jsonl | jq` to inspect rows
- Open the data in pandas with `pd.read_json(path, lines=True)`
